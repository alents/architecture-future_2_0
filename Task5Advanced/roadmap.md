# Стратегический роадмап внедрения Data Mesh

## 1. Контекст

Компания «Будущее 2.0» работает на монолитном DWH, который совмещает роли OLTP-системы и аналитического хранилища, содержит бизнес-логику всех направлений и обслуживает сотни терабайт данных. Формирование сложных отчётов занимает часы, масштабирование под новые бизнес-направления (финтех, ИИ, фарма) практически невозможно. Роадмап описывает переход к Data Mesh — архитектуре, в которой пять доменов (Медицинские услуги, Финтех/Банкинг, Корпоративные финансы, Операции, ИИ-сервисы) владеют собственными пайплайнами данных и самостоятельно публикуют витрины.

## 2. Ключевые роли

**Data Product Owner (DPO)** — представитель бизнеса в домене. Определяет, какие Data Products публикует домен, задаёт SLA по качеству и доступности, приоритизирует бэклог аналитических задач. Отвечает за описание бизнес-метрик в каталоге данных и согласование контрактов данных (data contracts) с другими доменами. На этапе пилота — совмещённая роль, далее — выделенная позиция в каждом домене.

**Data Engineer** — технический специалист, строящий пайплайн данных внутри домена: от захвата изменений (CDC / Transactional Outbox) и публикации событий в шину до потоковой обработки и записи в Lakehouse. Работает как в доменной команде (пайплайны конкретного домена), так и в платформенной (общая инфраструктура: событийная шина, федеративный слой запросов, IAM). В пилоте — инженеры из платформенной команды работают embedded в доменах, затем домены формируют собственные команды.

**BI-аналитик** — доменная роль. Валидирует качество Data Products совместно с DPO, наполняет каталог данных бизнес-описаниями витрин и метрик, помогает бизнес-пользователям работать с данными домена. Один аналитик на домен в пилоте, до двух-трёх при масштабировании.

## 3. Этапы внедрения

### Этап 1. Пилот (месяцы 1–6)

**Цель:** сформировать и согласовать архитектурное решение, определить границы доменов, запустить первые витрины в одном-двух доменах.

**Пилотные домены:** Корпоративные финансы и Медицинские услуги (пациентский поток) — выбраны как наиболее показательные для демонстрации ценности.

**Ключевые действия:**

- Формирование платформенной команды. Развёртывание событийной шины, потоковой обработки, Lakehouse в облаке. Настройка IAM. *(Data Engineer платформы)*
- Назначение DPO в пилотных доменах. Определение первых Data Products и SLA. *(DPO)*
- Настройка репликации данных из Legacy DWH в доменные Lakehouse для пилотных доменов. *(Data Engineer домена)*
- Развёртывание каталога данных, регистрация пилотных Data Products. Внедрение единых принципов работы с событиями: реестр схем, очереди ошибок (DLQ), паттерны обработки. *(Data Engineer + DPO)*
- Валидация качества первых Data Products, наполнение каталога бизнес-описаниями витрин. *(BI-аналитик + DPO)*

---

### Этап 2. Масштабирование (месяцы 7–18)

**Цель:** распространить Data Mesh на все пять доменов, обеспечить публикацию Data Products каждым доменом, начать переход от batch к near-real-time.

**Ключевые действия:**

- Онбординг оставшихся доменов: назначение DPO, выделение Data Engineer и BI-аналитиков в каждом домене. *(DPO + Data Engineer)*
- Подключение Transactional Outbox в доменных сервисах для публикации оперативных бизнес-событий. Репликация исторических данных из DWH в Lakehouse продолжается параллельно. *(Data Engineer)*
- Расширение каталога данных: все Data Products зарегистрированы, lineage покрывает все пайплайны. *(Data Engineer + DPO)*
- Валидация качества Data Products во всех доменах, наполнение каталога бизнес-описаниями. *(BI-аналитик + DPO)*
- Запуск near-real-time потоковых витрин в критичных доменах (финансовые расчёты, пациентский поток). *(Data Engineer + DPO)*

---

### Этап 3. Целевое состояние и поддержка доменов (месяцы 19–36)

**Цель:** полный отказ от легаси, событийная платформа как основа взаимодействия доменов, масштабирование по продуктам и географии.

**Ключевые действия:**

- Переход всех доменов на Transactional Outbox. Все события — явные бизнес-события. *(Data Engineer)*
- Near-real-time обработка во всех доменах. *(Data Engineer + DPO)*
- Интеграция фарм. компаний и производителя электроники как новых источников через стандартные Data Contracts. *(DPO + Data Engineer)*
- Гео-масштабирование: развёртывание платформы в новых регионах с учётом локальных регуляторных требований. *(DPO + Data Engineer платформы)*
- Монетизация ИИ-функций: публикация ML-метрик и статистики использования как Data Products. *(DPO ИИ + BI-аналитик)*
- Непрерывная поддержка доменов: развитие компетенций, аудит качества Data Products. *(Все роли)*
