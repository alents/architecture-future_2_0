# Технический радар — «Будущее 2.0»

Формат: ThoughtWorks Tech Radar. Статус отражает текущую рекомендацию на момент начала трансформации.

| Статус | Значение |
|--------|----------|
| **Adopt** | Рекомендуем к широкому применению. Зрелая технология или обязательный паттерн без альтернатив в данном контексте. |
| **Trial** | Рекомендуем попробовать. Верное направление, но выбор конкретного инструмента ещё уточняется или технология внедряется впервые. |
| **Assess** | Стоит изучить. Перспективная технология, требует оценки и прототипирования перед принятием решения. |
| **Hold** | Не использовать в новых проектах. Поддерживается только как мост совместимости при миграции. |

## Квадрант 1 — Архитектурные паттерны и методы

| Технология / Паттерн | Статус | Обоснование |
|----------------------|--------|-------------|
| Domain-Driven Design (DDD) | **Adopt** | Методологическая основа доменной декомпозиции. Определяет границы владения данными и бизнес-логикой. Без DDD невозможно выделить домены корректно. |
| Event-Driven Architecture (EDA) | **Adopt** | Обязательное требование кейса: целевая архитектура — слабосвязанная событийная платформа. Домены взаимодействуют через события, а не через прямые вызовы или общий DWH. |
| Anti-Corruption Layer (ACL) | **Adopt** | Изолирует новые домены от legacy DWH и ESB на период миграции. Без ACL новые домены унаследуют ограничения монолита. |
| Self-service BI | **Adopt** | Одна из двух ключевых бизнес-задач кейса. Сотрудник получает доступ к данным в рамках своего уровня доступа без участия IT. |
| Transactional Outbox | **Adopt** | Паттерн надёжной публикации событий из доменной БД в Kafka с exactly-once семантикой. Следствие принятого решения об EDA — применяется всегда при записи событий из сервиса. |
| Data Mesh | **Trial** | Организационно-архитектурный подход, основанный на четырёх принципах: домены как владельцы данных, данные как продукт (Data Product), самообслуживаемая платформа данных, федеративное управление. Trial — подход может не взлететь организационно, но даже частичное внедрение (доменная декомпозиция, Data Products) не противоречит общей архитектуре. |
| CQRS | **Assess** | Разделение команд и запросов. Перспективно для финтех-домена с высокой нагрузкой на чтение. Требует оценки перед внедрением. |
| Semantic Layer | **Assess** | Единые бизнес-определения метрик поверх Trino. Полезен при масштабировании числа доменов и пользователей, но не критичен на старте. |
| Batch ETL (монолитный) | **Hold** | Текущий подход через центральный DWH. Блокирует переход к near-real-time и масштабирование по доменам. Не применять в новых проектах. |

## Квадрант 2 — Платформы и инфраструктура

| Технология / Паттерн | Статус | Обоснование |
|----------------------|--------|-------------|
| Облачная инфраструктура | **Adopt** | Целевая среда исполнения. Обеспечивает эластичное масштабирование, геораспределение и отказоустойчивость. Выбор провайдера определяется регуляторными требованиями (152-ФЗ, требования ЦБ РФ). |
| Kubernetes (Managed) | **Adopt** | Стандарт оркестрации контейнеров. Managed-сервис у облачного провайдера снижает операционную нагрузку доменных команд. |
| Keycloak | **Adopt** | IAM для единой аутентификации и RBAC across all domains. Зрелый open-source стандарт. Все компоненты платформы проверяют права через Keycloak. |
| Object Storage (S3-совместимый) | **Adopt** | Базовый уровень Data Lake. Масштабируемое и дешёвое хранилище сырых данных всех доменов. Фундамент для табличного формата Lakehouse. |
| Infrastructure as Code (Terraform) | **Adopt** | Управление облачной инфраструктурой как код. Без IaC нет воспроизводимости сред и аудируемости изменений. |
| GitLab CI/CD | **Adopt** | Стандарт delivery pipeline для доменных команд. |
| PostgreSQL | **Adopt** | Операционная OLTP-база для доменных сервисов. Зрелая, надёжная, нативно поддерживается Debezium CDC. |
| Microsoft SQL Server 2008 | **Hold** | EOL с 2019 года. Не масштабируется, несовместим с облаком. Сохраняется только как мост совместимости на период миграции. |
| PowerBuilder | **Hold** | Устаревший клиентский интерфейс операторов клиник. Заменяется при переносе операционных систем в облако. |

## Квадрант 3 — Данные и аналитика

| Технология / Паттерн | Статус | Обоснование |
|----------------------|--------|-------------|
| Apache Kafka | **Adopt** | Центральная шина событий платформы. Де-факто стандарт для event streaming в enterprise-масштабе: exactly-once, retention, replay. Реальных альтернатив для данного сценария нет (RabbitMQ — message broker, не streaming platform). |
| Starburst / Trino | **Adopt** | Федеративный query engine — единая точка доступа для кросс-доменной аналитики без перемещения данных. Единственный open-source инструмент с сертифицированным нативным коннектором к Power BI (DirectQuery). |
| Apache Flink | **Trial** | Domain Stream Processing — потоковая обработка событий внутри домена и запись в Lakehouse. Trial — рекомендован для stateful streaming, но выбор между Flink и альтернативами уточняется в пилоте. |
| Apache Iceberg | **Trial** | Открытый табличный формат для Domain Lakehouse: ACID, schema evolution, time travel. Trial — де-факто лидер open-source экосистемы, но есть реальные альтернативы (Delta Lake, Apache Hudi). Выбор фиксируется через ADR по итогам пилота. |
| ClickHouse | **Trial** | Domain OLAP Store — ускоритель для интерактивных дашбордов (sub-second latency). Каждый домен самостоятельно решает о необходимости. Trial — есть альтернативы: Apache Druid, DuckDB. |
| DataHub | **Trial** | Каталог данных с веб-интерфейсом, автоматическим lineage через агент и бизнес-глоссарием. Trial — рассматривается совместно с OpenMetadata, выбор через пилот. |
| OpenMetadata | **Trial** | Альтернативный каталог данных с развитым UI и data quality интеграцией. Trial — оцениваем совместно с DataHub. |
| DataLens | **Trial** | BI-инструмент облачного провайдера. Trial — для новых доменов без legacy-дашбордов, оцениваем как долгосрочную замену Power BI. |
| Apache Superset | **Assess** | Open-source BI как резервный вариант. Assess — если DataLens окажется недостаточным для сложного ad-hoc анализа. |
| Delta Lake | **Assess** | Альтернативный табличный формат Lakehouse от Databricks. Assess — сравниваем с Apache Iceberg в рамках пилота. |
| Power BI | **Hold** | Облачная версия (Power BI Service) недоступна на территории РФ с мая 2024 г. (санкции ЕС, 12-й пакет). Существующие дашборды сохраняются, новые не строятся. Замена — DataLens или Apache Superset. |

## Квадрант 4 — Интеграция и стриминг

| Технология / Паттерн | Статус | Обоснование |
|----------------------|--------|-------------|
| REST API (OpenAPI) | **Adopt** | Стандарт синхронных интеграций между доменами. Базовый протокол для операционных запросов. |
| Debezium CDC | **Adopt** | Захват изменений из доменной БД в Kafka. Переходный этап — читает legacy-системы без переписывания сервисов. Целевой этап — читает Outbox-таблицу. Де-факто стандарт CDC для PostgreSQL. |
| Dead Letter Queue (DLQ) | **Adopt** | Обработка ошибок в event-driven потоках. Без DLQ потерянные события невосстановимы. Обязателен с первого пилота. |
| Camel K | **Assess** | Облачная версия Apache Camel на Kubernetes. Assess — возможный переходный шаг при модернизации ESB вместо полной замены. |
| Apache Camel ESB | **Hold** | Текущая интеграционная шина. Не развивается. Сохраняется только как мост совместимости на период миграции к event-driven архитектуре. |
